# Research Quality

Read this only when research **completed successfully** but its evidence is
empty, irrelevant, sparse or too indirect for the user's question. Execution
failures follow `shared-public-skill-rules.md`; changing a query or provider must
not conceal an auth, compatibility, network or unfinished-task failure.

Inspect the records, not just the exit code or count. Check that their type,
content, source and date can support the question. Adjacent evidence can guide a
follow-up, but cannot establish the main conclusion.

If a follow-up is useful, explain the gap and choose a focused change: query,
entity, route, geography, language or time window. Use only supported routes and
keep each result attributable to its actual scope. Do not repeat the same request
or fabricate missing evidence. Allow at most two follow-up passes within the
already approved scope and budget; new spending still needs its required approval.

Stop when the evidence is sufficient, the bound is reached, or a further pass
would not help. Report the useful findings and remaining uncertainty in ordinary
language. Do not require a fixed report template or call an empty result a success.
